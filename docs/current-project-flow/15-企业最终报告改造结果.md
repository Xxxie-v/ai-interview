# 企业最终报告改造结果

## 1. 复用了什么

最终报告没有重写原有面试评分链路，而是复用：

- `AnswerEvaluationService` 和 `UnifiedEvaluationService` 的逐题结构化评分；
- `InterviewSessionService.generateReport()` 的基础报告；
- `LlmProviderRegistry` 的多模型路由；
- `StructuredOutputInvoker` 的结构化输出解析与重试；
- 已有简历、岗位 JD、问题和回答数据；
- 客观视觉事件记录。

在基础报告之上新增一次企业维度汇总，生成技术、沟通和岗位匹配分数，以及优势、不足、
需人工复核的风险备注、摘要和建议。

## 2. 核心流程

```text
管理员/获授权候选人请求最终报告
  -> 校验会话状态和访问权限
  -> 已有 interview_reports 记录：直接返回
  -> 没有记录：复用原有逐题 AI 评估
  -> 加入岗位 JD 与结构化问答评分
  -> StructuredOutputInvoker 生成企业维度报告
  -> 单独事务保存 interview_reports
  -> 附加客观视觉事件 DTO 后返回
```

外部 LLM 调用和数据库保存被拆开，LLM 调用不在事务中执行。`session_id` 有唯一约束，正常
重复读取不会再次生成报告。

## 3. 报告字段

- `overallScore`：复用已有面试综合分；
- `technicalScore`：技术能力评分；
- `communicationScore`：回答表达和沟通评分；
- `jobMatchScore`：与岗位 JD 的匹配评分；
- `strengths`、`weaknesses`：证据化优势和不足；
- `riskNotes`：需要人工复核的能力证据缺口或回答矛盾；
- `summary`、`recommendation`：简短可审核摘要和人工决策建议；
- `objectiveVisionEvents`：过程中的客观画面事件。

视觉事件不参与技术、沟通或岗位匹配评分，也不用于推断诚信、情绪、性格或自动录用结论。

## 4. 权限与防泄漏

管理员接口：

```http
GET /api/admin/interviews/{sessionId}/report
```

要求 `ADMIN` 角色，并记录管理员查看报告的审计日志。

候选人接口：

```http
GET /api/interviews/{sessionId}/report
```

候选人必须是会话所有者。正式面试还必须关联面试任务，且任务的
`reportVisibleToCandidate=true`。普通模拟面试保持原来的本人可见行为。

同时修复了两个旁路：未开放正式报告时，候选人的面试列表和简历详情不再返回综合分和评估
错误；旧报告、详情和 PDF 接口也执行同一可见性校验。

## 5. 面试任务关联

候选人从岗位发起面试时，系统会按候选人、岗位、简历和有效状态查找最近的面试任务，并把
任务 ID 写入会话。这样管理员创建任务时设置的报告可见性可以实际约束最终报告。

没有匹配任务的公开岗位面试仍可进行，但正式报告默认不向候选人开放，管理员始终可以查看。

## 7. 数据库变化

新增 `interview_reports` 表，包含：

- 唯一会话 ID；
- 可选任务 ID；
- 四类分数；
- 优势、不足和风险 JSON；
- 摘要、建议和生成时间；
- 任务与生成时间索引。

项目规范要求开发环境由 JPA Entity 驱动表结构，生产环境 `ddl-auto=false`，当前项目未使用
Flyway/Liquibase，因此本阶段没有额外迁移脚本。生产部署前应根据实体生成并审核正式 DDL。

## 8. 测试与查看方式

- `EnterpriseInterviewReportServiceTest` 覆盖隐藏报告、跨用户越权、缓存报告复用和首次生成；
- 全量后端测试通过；
- 前端 TypeScript 检查和 Vite 生产构建通过；
- 管理员进入“正式面试结果”，展开某场面试后点击“企业报告”即可查看四维分数和摘要。
