# 快速组卷与回答驱动追问改造结果

## 1. 改造目标

正式面试不再在候选人点击“参加面试”后串行调用两次 AI 出题。新的题目来源为：

- 岗位固定题 3～6 道：岗位创建时从项目已有 Skill 参考题库中随机抽取并固定保存；
- 简历题 3～6 道：简历上传并完成解析后，在 Redis Stream 消费线程中提前生成并保存；
- 动态追问：候选人回答后，根据当前回答实时决定是否追问。

默认配置为岗位题池 6 道、简历预生成 6 道。默认一场 8 道主问题时，实际选择 4 道岗位题和
4 道简历题。

## 2. 新流程

```text
创建岗位
  -> 根据岗位文本识别 Skill
  -> 从已有 references 本地抽取 6 道题
  -> fixed_questions_json

上传简历
  -> 文档解析
  -> 异步简历分析
  -> 异步生成 6 道简历题
  -> prepared_questions_json

点击参加面试
  -> 前端立即展示摄像头/麦克风调试
  -> 后端同时创建会话
  -> 读取岗位固定题 + 简历预生成题
  -> 本地组卷、去掉所有预设追问、重新编号
  -> 设备与题目都准备好后允许开始面试
```

如果旧简历尚无预生成题，后端会在设备调试期间补生成一次。以后新上传的简历通常会直接命中
预生成结果。

## 3. 岗位固定题

`InterviewSkillService.loadQuestionBank()` 从现有 `skills/_shared/references/*.md` 中读取题库
条目。`JobQuestionBankService` 根据岗位文本选择 Java、Python、前端、AI Agent、算法或测试
Skill，再随机抽取固定题。

固定题在岗位创建时保存。只修改岗位状态不会重新抽题；岗位名称、描述或要求变化时才会重新
抽取。旧岗位第一次参加面试时会自动补齐固定题。

## 4. 简历题预生成

`ResumeEntity` 新增：

- `questionPrepareStatus`；
- `questionPrepareError`；
- `preparedQuestionsJson`；
- `questionsPreparedAt`。

`AnalyzeStreamConsumer` 保存简历分析后调用 `ResumeQuestionPreparationService`。失败只标记题目
准备状态，不会删除简历；正式面试创建时仍可以进行补生成。

## 5. 回答驱动追问

所有出题 Prompt 都要求 `followUps=[]`，`InterviewQuestionService` 也会忽略模型返回的预设
追问。因此新会话中不存在提前写死的追问题。

候选人提交答案后，`DynamicFollowUpService` 接收：

- 当前问题；
- 当前考察方向和知识点；
- 候选人的本次回答；
- 最近五轮问答历史。

只有本次回答出现值得验证的概念、方案、数据或矛盾点时才生成追问。模型不可用时，降级追问
也会引用本次回答的原文片段，不再返回固定问题。

## 6. 配置

```properties
APP_INTERVIEW_OFFICIAL_MIN_QUESTIONS_PER_SOURCE=3
APP_INTERVIEW_OFFICIAL_MAX_QUESTIONS_PER_SOURCE=6
APP_INTERVIEW_JOB_FIXED_QUESTION_COUNT=6
APP_INTERVIEW_RESUME_PREPARED_QUESTION_COUNT=6
APP_INTERVIEW_DYNAMIC_MAX_TOTAL_QUESTIONS=18
```

动态最大题数包含实时插入的追问，因此从原来的 12 调整为 18；单方向追问次数仍受
`APP_INTERVIEW_DYNAMIC_MAX_FOLLOW_UPS_PER_TOPIC` 控制。

## 8. 数据库变化

- `job_position.fixed_questions_json`；
- `resumes.question_prepare_status`；
- `resumes.question_prepare_error`；
- `resumes.prepared_questions_json`；
- `resumes.questions_prepared_at`。

这些字段均允许为空，以兼容已有岗位和简历；旧数据按需自动补齐。项目开发环境继续由 JPA
Entity 更新表结构，没有新增手写迁移脚本。

## 9. 测试

- `InterviewPlannerServiceTest`：命中缓存时直接组合 3 道岗位题和 3 道简历题，不调用 AI；
- `ResumeQuestionPreparationServiceTest`：异步预生成题成功保存；
- `JobPositionServiceTest`：创建岗位时保存固定题；
- `DynamicFollowUpServiceTest`：降级追问仍引用候选人本次回答；
- 后端全量测试、TypeScript 检查和 Vite 构建均需通过后再运行。
