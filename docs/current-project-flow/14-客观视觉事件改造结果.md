# 客观视觉事件改造结果

## 1. 本阶段解决什么问题

本阶段给正式视频面试增加了低频画面抽样和客观事件记录能力。它只描述可观察到的技术事实：

- 摄像头是否中断；
- 画面是否过暗；
- 画面是否未检测到人脸；
- 画面是否检测到多张人脸。

这些事件不用于推断候选人的情绪、性格、诚信或是否应该录用。管理员界面也明确展示了这一
限制。

## 2. 当前能力边界

当前默认 Provider 是 `mock`：

- 低光事件来自浏览器对抽样画面的平均亮度计算，是真实采样指标；
- 摄像头中断来自浏览器媒体轨道状态，是真实设备状态；
- 人脸缺失和多人事件目前由 Mock 配置模拟，只用于打通接口、存储和界面流程；
- 接入真实计算机视觉服务后，只需实现 `VisionAnalyzerProvider`，不需要改变控制器和前端协议。

因此，当前版本不能宣称已经具备真实的人脸数量识别能力。

## 3. 数据流

```text
InterviewPage
  -> interviewVisionMonitor（默认每 5 秒抽一帧，320x180 JPEG）
  -> POST /api/interviews/{sessionId}/vision/analyze
  -> InterviewVisionService（归属、大小、类型和文件签名校验）
  -> RoutingInterviewVisionAnalyzer
  -> MockInterviewVisionAnalyzer
  -> InterviewVisionEventPersistenceService（同类事件冷却去重）
  -> interview_vision_events
```

浏览器抽帧仅用于当次分析。后端不把原始图片写入对象存储或数据库，只保存事件类型、发生
时间、持续时间和客观指标 JSON。实体预留了证据对象键，但当前始终为空。

## 5. 接口与权限

### 候选人提交抽样画面

```http
POST /api/interviews/{sessionId}/vision/analyze
Content-Type: multipart/form-data
```

字段为 `frame`、`brightness` 和 `cameraActive`。接口要求 `INTERVIEWEE` 角色，并再次校验
会话属于当前用户。用户维度默认限流为每分钟 30 次。

### 管理员查看事件

```http
GET /api/admin/interviews/{sessionId}/vision-events
```

接口只允许 `ADMIN` 角色。管理员可在“正式面试结果”中展开候选人的面试记录，再点击
“过程事件”查看。

## 6. 配置

主要配置位于 `application.yml` 的 `app.interview.vision`：

```yaml
enabled: true
provider: mock
frame-interval: PT5S
max-frame-size: 1048576
event-cooldown: PT30S
low-light-threshold: 40
```

前端抽样间隔由 `VITE_INTERVIEW_VISION_FRAME_MS` 控制，默认 5000 毫秒。后端的
`frame-interval` 同时用于记录单个事件的估计持续时间。

## 7. 安全与隐私约束

- 只接受 JPEG/PNG，并校验文件头签名和最大体积；
- 候选人不能向其他用户的会话提交画面；
- 同一会话同类事件在冷却时间内不会重复落库；
- 原始抽帧不持久化；
- API 返回给管理员的 DTO 不暴露内部对象存储键；
- 不做身份识别，不使用敏感生物特征模板，不做情绪或人格推断。
