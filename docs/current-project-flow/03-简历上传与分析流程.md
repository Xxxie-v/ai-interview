# 简历上传与分析流程

## 主流程

```text
POST /api/resumes/upload
  -> ResumeController
  -> ResumeUploadService.uploadAndAnalyze
  -> FileValidationService / ContentTypeDetectionService
  -> FileHashService 计算 SHA-256
  -> ResumePersistenceService 按 ownerUserId + fileHash 去重
  -> FileStorageService 上传 RustFS
  -> DocumentParseService 使用 Tika 解析
  -> ResumeEntity 入库，analyzeStatus=PENDING
  -> AnalyzeStreamProducer 写入 Redis Stream
  -> 立即返回上传结果

Redis Stream Consumer
  -> AnalyzeStreamConsumer
  -> 校验 ResumeEntity 仍存在
  -> ResumeGradingService
  -> LlmProviderRegistry 获取 ChatClient
  -> StructuredOutputInvoker 解析结构化评分
  -> ResumeAnalysisEntity 入库
  -> analyzeStatus=COMPLETED/FAILED
```

## 归属控制

当前简历已经带有 `ownerUserId`，Controller 从 `AuthPrincipal` 获取用户 ID，Repository 使用
`findByIdAndOwnerUserId` 等方法限制读取、删除、重新分析和导出。这是后续统一
`ResumePermissionService` 的基础。
