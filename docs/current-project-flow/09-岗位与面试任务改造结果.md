# 岗位与面试任务改造结果

这一阶段把“管理员发布岗位并给候选人分配面试”接入了现有系统。它位于登录鉴权之后、
正式开始面试之前，是企业招聘流程的中间层。

## 一、先看页面

- 管理员页面：`http://localhost:5173/admin/recruitment`
- 候选人页面：`http://localhost:5173/jobs`

管理员页面包含“岗位管理”和“面试任务”两个区域。管理员可以创建岗位、调整岗位状态，
并选择候选人、候选人的简历和截止时间创建面试任务。候选人端则以主动应聘为主：管理自己的
简历、查看招聘中的岗位，并选择一份自己的简历参加岗位 AI 面试。

## 二、最容易理解的业务流程

```text
管理员创建岗位
    ↓
岗位状态改为 ACTIVE（招聘中）
    ↓
候选人先上传简历
    ↓
候选人查看 ACTIVE（招聘中）的岗位
    ↓
选择简历和岗位，参加 AI 面试
    ↓
后端根据数据库中的简历正文 + 岗位 JD 生成针对性问题
```

## 三、后端代码从哪里读

建议按下面顺序阅读：

1. `modules/recruitment/AdminJobController.java`：管理员岗位接口入口。
2. `modules/recruitment/service/JobPositionService.java`：岗位增删改查规则。
3. `modules/recruitment/model/JobPositionEntity.java`：岗位在数据库中的结构。
4. `modules/recruitment/AdminInterviewAssignmentController.java`：管理员分配任务入口。
5. `modules/recruitment/service/InterviewAssignmentService.java`：任务校验、创建和查询规则。
6. `modules/recruitment/model/InterviewAssignmentEntity.java`：任务在数据库中的结构。
7. `modules/recruitment/IntervieweeAssignmentController.java`：候选人查看自己任务的入口。
8. `modules/recruitment/IntervieweeJobController.java`：候选人查看招聘中岗位的入口。

核心安全规则在 `InterviewAssignmentService` 中：

- 只能给启用状态的 `INTERVIEWEE` 用户分配任务。
- 只能选择状态为 `ACTIVE` 的岗位。
- 所选简历必须属于被分配的候选人。
- 截止时间不能早于可开始时间。
- 候选人查询详情时，数据库查询同时使用任务 ID 和当前用户 ID，不能查看别人的任务。

## 四、接口清单

管理员岗位接口（仅 `ADMIN`）：

- `POST /api/admin/jobs`：创建岗位。
- `PUT /api/admin/jobs/{jobId}`：修改岗位。
- `DELETE /api/admin/jobs/{jobId}`：删除尚未被任务使用的岗位。
- `GET /api/admin/jobs/{jobId}`：查看岗位详情。
- `GET /api/admin/jobs`：分页查询岗位。

管理员任务接口（仅 `ADMIN`）：

- `POST /api/admin/interview-assignments`：创建面试任务。
- `GET /api/admin/interview-assignments`：分页查询全部任务。
- `GET /api/admin/interview-assignments/{assignmentId}`：查看任务详情。
- `GET /api/admin/users/{candidateId}/resumes`：查询指定候选人的简历供下拉框选择。

候选人接口（仅 `INTERVIEWEE`）：

- `GET /api/interviewee/assignments`：分页查询自己的任务。
- `GET /api/interviewee/assignments/{assignmentId}`：查看自己的任务详情。
- `GET /api/interviewee/jobs`：查询所有招聘中的岗位。

## 五、数据库变化

新增两张由 JPA Entity 管理的表：

- `job_position`：岗位名称、部门、描述、要求、地点、雇佣类型、状态和审计时间。
- `interview_assignment`：候选人、岗位、简历、可开始时间、截止时间、状态、创建人等。

按照本项目规则，开发环境由 `spring.jpa.hibernate.ddl-auto=update` 根据 Entity 自动更新表结构，
没有另写数据库迁移脚本。

## 六、前端代码从哪里读

- `frontend/src/pages/AdminRecruitmentPage.tsx`：管理员岗位和任务页面。
- `frontend/src/pages/MyAssignmentsPage.tsx`：候选人的岗位选择页面。
- `frontend/src/api/recruitment.ts`：上述页面实际调用的后端接口。
- `frontend/src/App.tsx`：页面路由和角色保护。
- `frontend/src/components/Layout.tsx`：左侧菜单入口。

## 七、已经验证的内容

- 后端完整测试：`gradlew.bat :app:test` 通过。
- 前端 TypeScript 检查：`npx tsc --noEmit` 通过。
- 前端 Vite 生产构建：`npx vite build` 通过。
- 单元测试覆盖岗位默认状态、已有任务时禁止删除、简历归属校验、任务越权访问和正常创建。
- 单元测试覆盖候选人只能看到招聘中岗位，以及没有简历时不能发起岗位面试。

## 八、当前边界

候选人主动选择岗位后，当前会进入已有文字 AI 面试链路；面试请求会保存 `jobId`，服务端强制
校验岗位状态和简历归属，并使用数据库中的简历和 JD 出题。任务到期状态的持久化以及统一的
面试状态流转，仍在下一阶段的状态机改造中实现。
