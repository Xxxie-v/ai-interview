# 简历只出题与人工审核状态改造结果

## 新的简历流程

上传简历后只执行以下步骤：

1. 校验、解析并保存简历文件；
2. 将简历出题任务写入 Redis Stream；
3. 后台生成 3～6 道简历面试题并保存到 `preparedQuestionsJson`。

上传流程不再调用 `ResumeGradingService`，也不再生成简历分数、优势、建议或简历分析报告。
前端简历管理页展示 `questionPrepareStatus`：等待出题、正在出题、题目已准备、出题失败。

## 新的面试审核状态

面试执行状态继续用于内部状态机；面试记录对外使用独立的 `reviewStatus`：

| 状态 | 页面文案 | 含义 |
|---|---|---|
| `INCOMPLETE` | 未完成 | 候选人尚未完成面试 |
| `COMPLETED` | 已完成 | 候选人已经提交，等待 HR 审核 |
| `UNDER_MANUAL_REVIEW` | 人工审核中 | HR 已开始审核 |
| `PASSED` | 通过 | 人工审核通过 |
| `REJECTED` | 不通过 | 人工审核不通过 |

HR 可通过 `PATCH /api/hr/interview-results/{sessionId}/review-status` 更新审核状态。
状态流转为：

`已完成 → 人工审核中 → 通过/不通过`

通过或不通过后可以重新进入人工审核。未完成的面试不允许直接设置审核结论。

## 分数处理

面试记录列表、候选人面试详情和 HR 正式面试列表不再展示总分或单题得分。
回答质量判断仍可作为动态追问和内部辅助报告的输入，但不会自动形成通过或不通过结论。
