# 第四阶段：面试状态机与动态追问改造结果

这一阶段在保留原文字面试 API 的前提下，为岗位正式面试增加了企业级流程状态、乐观锁、
简历加岗位 JD 的统一规划服务，以及根据候选人实际回答生成的动态追问。

## 一、现在的岗位面试流程

```text
候选人选择岗位和自己的简历
    ↓
InterviewPlannerService 使用数据库中的简历 + 岗位 JD 生成主问题
    ↓
READY → QUESTIONING
    ↓
提交回答：QUESTIONING → ANSWERING → EVALUATING
    ↓
逐题结构化评估：澄清 / 深挖 / 换方向 / 结束
    ↓
继续时回到 QUESTIONING，全部完成后进入 FINISHED
```

岗位面试不再提前生成固定追问。只有回答后，`DynamicFollowUpService` 才会结合当前问题、
回答和最近五条问答决定是否插入追问。

## 二、状态机

新增状态：

```text
INIT
DEVICE_CHECK
READY
QUESTIONING
ANSWERING
EVALUATING
PAUSED
FINISHED
TERMINATED
```

`InterviewStateMachineService` 保存允许的状态转换。非法回退会抛出业务异常，例如已经
`FINISHED` 的面试不能重新进入 `QUESTIONING`。

实体新增 `@Version` 乐观锁字段，数据库并发更新同一会话时会检测版本冲突。旧的
`CREATED / IN_PROGRESS / COMPLETED / EVALUATED` 字段暂时保留并同步更新，以兼容现有页面、
历史数据和异步评估流程。

## 三、动态追问安全边界

- 使用 `StructuredOutputInvoker` 获取结构化逐题评估结果。
- `NextAction` 只有 `DEEP_FOLLOW_UP / CLARIFY / NEW_TOPIC / FINISH`。
- 只把最近五条已回答问题传给模型，不传无关完整历史。
- 问题、回答和历史文本经过 `PromptSanitizer` 清洗及随机边界包裹。
- `reasoningSummary` 限制长度，并且不返回前端。
- 默认总题数上限 12，每个方向最多动态追问 1 次。
- 模型暂时不可用时，短回答使用一条固定澄清问题，其他回答切换新方向。

## 四、答案提交幂等

`POST /api/interview/sessions/{sessionId}/answers` 现在要求请求头：

```text
Idempotency-Key: 一个不重复的请求标识
```

前端使用 `crypto.randomUUID()` 生成。服务端按“会话 + 幂等键”加 Redis 锁并缓存结果 24 小时，
防止双击、超时重试或并发请求造成重复保存答案和重复出题。服务端同时要求提交的问题索引
必须等于会话当前索引。

## 五、新增接口

- `GET /api/interview/sessions/{sessionId}/status`：候选人查看自己的流程状态。
- `POST /api/interview/sessions/{sessionId}/pause`：暂停自己的进行中面试。
- `POST /api/interview/sessions/{sessionId}/resume`：恢复已暂停面试。
- `POST /api/admin/interview-sessions/{sessionId}/terminate`：管理员终止异常会话。

候选人接口继续使用资源归属校验，修改 URL 中的 `sessionId` 不能访问他人会话。

## 六、数据库变化

`interview_sessions` 新增：

- `job_id`
- `assignment_id`（为管理员分配任务接入会话预留）
- `flow_status`
- `started_at`
- `ended_at`
- `version`

项目没有 Flyway/Liquibase，开发环境继续由 JPA `ddl-auto=update` 根据 Entity 更新结构。

## 七、配置项

```text
APP_INTERVIEW_DYNAMIC_MAX_TOTAL_QUESTIONS=12
APP_INTERVIEW_DYNAMIC_MAX_FOLLOW_UPS_PER_TOPIC=1
```

对应配置集中在 `InterviewQuestionProperties`，没有在业务 Service 中散落 `@Value`。

## 八、重要代码阅读顺序

1. `InterviewFlowStatus.java`：完整状态列表。
2. `InterviewStateMachineService.java`：合法状态转换。
3. `InterviewPlannerService.java`：简历 + JD 出题入口。
4. `DynamicFollowUpService.java`：逐题评估和追问决策。
5. `InterviewSessionService.java`：把状态、回答保存、动态追问串起来。
6. `InterviewController.java`：候选人状态、暂停、恢复和提交接口。
7. `AdminInterviewSessionController.java`：管理员终止接口。

## 九、测试

新增测试覆盖：

- `READY → QUESTIONING` 合法转换并记录开始时间。
- `FINISHED → QUESTIONING` 非法回退。
- 岗位面试规划移除预生成追问。
- 岗位面试没有简历时拒绝创建。

后端完整测试、前端 TypeScript 检查和生产构建均需通过后，才进入下一阶段。

## 十、当前边界

本阶段接入的是已有文字面试链路。`DEVICE_CHECK` 状态已经预留，但摄像头、麦克风权限检测和
视频录制属于第五、六阶段；实时 WebSocket 事件流也在下一阶段实现。
