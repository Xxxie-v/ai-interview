# 第六阶段：设备检测与视频分片上传改造结果

这一阶段为正式岗位面试增加了摄像头、麦克风检查和浏览器视频分片录制。普通模拟面试
仍保持原来的文字答题流程，不会请求摄像头权限。

## 一、候选人操作流程

```text
创建正式面试会话
  -> 服务端状态 DEVICE_CHECK
  -> 候选人点击“检测摄像头和麦克风”
  -> 浏览器弹出设备授权
  -> 页面显示本地实时预览和设备状态
  -> 候选人点击“同意录制并开始面试”
  -> 服务端状态 READY / QUESTIONING
  -> MediaRecorder 每约 25 秒生成分片
  -> SHA-256 校验并异步上传到 RustFS/S3
  -> 面试结束时上传最后分片并释放 MediaStream Track
```

摄像头和麦克风不会在页面加载时自动开启。只有候选人主动点击检测按钮后才请求权限，
只有再次明确点击开始面试后才开始录制。

## 二、设备异常

前端会区分并提示：

- 权限被拒绝。
- 找不到摄像头或麦克风。
- 设备被其他软件占用。
- 当前浏览器不支持媒体设备接口。

设备检查未完成时，正式面试后端状态保持 `DEVICE_CHECK`，不能直接发送开始事件绕过门禁。

## 三、视频接口

```text
POST /api/interviews/{sessionId}/videos/chunks
POST /api/interviews/{sessionId}/videos/complete
GET  /api/interviews/{sessionId}/videos
GET  /api/admin/interviews/{sessionId}/videos
```

分片上传使用 `multipart/form-data`：

```text
file         视频 Blob
chunkIndex   从 0 开始的连续序号
durationMs   分片时长
checksum     客户端计算的 SHA-256
```

## 四、安全与幂等

- Controller 和 Service 都会校验会话归属。
- 数据库使用 `(session_id, chunk_index)` 唯一约束。
- 相同序号、相同 checksum 的成功分片直接返回，不重复写入对象存储。
- 相同序号上传不同内容会被拒绝。
- 服务端会重新计算 SHA-256，不能只相信客户端 checksum。
- 单分片默认最大 25 MiB，并校验允许的 MIME 类型。
- 对象键由服务端 UUID 随机生成，不使用用户文件名。
- API 只返回视频元数据，不暴露永久对象存储 URL。
- 管理员查询视频元数据会记录审计日志。

## 五、存储设计

新增 `ObjectStorageService` 接口，并由 `S3ObjectStorageService` 实现上传、删除和短期签名
URL。视频业务不直接依赖 S3 SDK。

考虑到本地开发没有运行 Docker/RustFS，默认使用 `LocalObjectStorageService` 写入本机临时
目录；生产环境设置 `APP_STORAGE_PROVIDER=s3` 后切换到 RustFS/S3。简历、知识库和视频
共用这一抽象，本地运行不再依赖 9000 端口。

外部对象上传不放在数据库事务中：

1. 短事务预留分片记录，状态为 `UPLOADING`。
2. 事务外上传对象存储。
3. 新的短事务将状态更新为 `UPLOADED` 或 `FAILED`。

## 六、数据库结构

新增 JPA 实体 `InterviewVideoEntity`，对应 `interview_videos` 表，主要字段包括：

- `session_id`、`user_id`
- `object_key`、`mime_type`、`file_size`
- `duration_ms`、`chunk_index`、`checksum`
- `status`、`created_at`、`updated_at`

本项目开发环境使用 JPA `ddl-auto=update`，因此没有额外迁移脚本；启动后由实体注解更新
表结构。生产环境部署时应根据该实体生成并审核正式 DDL。

## 九、测试结果

新增单元测试覆盖：

- 非会话所有者上传被拒绝。
- checksum 不一致时拒绝上传。
- 已成功的相同分片不会重复写入对象存储。
- 新分片上传成功后更新状态。

项目全部后端测试、前端 TypeScript 检查和生产构建均已通过。

## 十、当前边界

本阶段保存独立视频分片和元数据，没有在 Java 进程内执行视频转码或合并。视频合并更适合
后续通过独立媒体任务处理，避免阻塞面试问答和占用应用服务器资源。

过期分片由每天凌晨运行的清理任务分批删除，默认保存 30 天。
